1. SCOPE & HOISTING (var vs let vs const)
--------------------------------------------------------------------------------
* Scope Types:
  - Global Scope: Accessible everywhere in the application.
  - Function/Local Scope: Variables declared with `var`, `let`, or `const` inside a function are accessible only within that function.
  - Block Scope: Variables declared with `let` or `const` inside curly braces `{}` are accessible only inside that block.

* Comparison Matrix: var vs let vs const
  +-------------+----------------+------------------+-----------------------+
  | CHARACTER   | var            | let              | const                 |
  +-------------+----------------+------------------+-----------------------+
  | Scope       | Function Scope | Block Scope      | Block Scope           |
  | Redeclaring | Yes            | No               | No                    |
  | Updating    | Yes            | Yes              | No (re-binding fails) |
  | Hoisted     | Yes (undefined)| Yes (uninit/TDZ) | Yes (uninit/TDZ)      |
  +-------------+----------------+------------------+-----------------------+
  Note: Objects and arrays declared with `const` can have their properties or elements mutated.
  The constraint is that the variable name itself cannot be reassigned to point to a new value/reference.

* Hoisting Mechanics:
  - Definition: The JavaScript engine moves variable and function declarations to the top of their containing scope during the compilation phase before execution.
  - JS Engine Life Cycle:
    1. Creation/Compilation Phase: Scanner scans scope, allocates memory for variables and functions.
       - Functions are fully stored in memory.
       - Variables declared with `var` are allocated and initialized with `undefined`.
       - Variables declared with `let` and `const` are allocated but left uninitialized.
    2. Execution Phase: Values are assigned as lines are executed sequentially.

* Temporal Dead Zone (TDZ):
  - The state/time interval starting from the block entry until the variable's declaration statement is executed.
  - Attempting to access the variable during the TDZ triggers a `ReferenceError`.
  - Example:
    {
      // --- TDZ starts here for x ---
      // console.log(x); // ReferenceError: Cannot access 'x' before initialization
      let x = 10;      // --- TDZ ends here for x ---
      console.log(x);  // 10 (safe to access)
    }

2. DATA TYPES & COMPARISON
--------------------------------------------------------------------------------
* Data Categories:
  1. Primitive Types (Value-Based):
     - Stored directly in the call stack (fixed size).
     - Immutable: Operations return a new primitive; they do not alter the original.
     - Types: `string`, `number`, `boolean`, `undefined`, `null`, `symbol`, `bigint`.
  2. Reference Types (Reference-Based):
     - Stored in the heap (dynamic size). The stack holds a pointer/address references to the heap memory.
     - Mutable: Can be modified directly without re-binding.
     - Types: `object` (including arrays `[]`, functions `() => {}`, dates, regular expressions).

* Equality Operators & Coercion Rules:
  - Loose Equality (`==`):
    - Performs implicit type coercion if operands are different types before evaluating value.
    - Coercion hierarchy:
      1. If one operand is Boolean, it's converted to Number (`true -> 1`, `false -> 0`).
      2. If String and Number, String is converted to Number.
      3. If Object and Primitive, Object is converted to Primitive (via `valueOf()` and `toString()`).
      4. `null` and `undefined` equal each other loosely, and nothing else.
    - Gotcha Example: `[] == ![]` resolves to `true` (Steps: `![]` becomes `false`; `[] == false` converts both to numbers: `0 == 0` -> true).
  - Strict Equality (`===`):
    - Returns true only if values have the same type and the same value.
    - No type coercion occurs.
    - Reference variables compare their reference address (two objects with identical key-values are not equal).
  - Object.is(a, b):
    - Determines if two values are the same value.
    - Differs from `===` in two edge cases:
      1. `NaN === NaN` is `false`, but `Object.is(NaN, NaN)` is `true`.
      2. `-0 === +0` is `true`, but `Object.is(-0, +0)` is `false`.

3. FUNCTIONS & 'this' KEYWORD
--------------------------------------------------------------------------------
* Regular vs. Arrow Functions:
  +----------------------+--------------------------+-----------------------+
  | FEATURE              | REGULAR FUNCTION         | ARROW FUNCTION        |
  +----------------------+--------------------------+-----------------------+
  | 'this' Binding       | Dynamic (how invoked)    | Lexical (inherited)   |
  | arguments Object     | Yes                      | No (use ...args)      |
  | Constructor (new)    | Yes                      | No                    |
  | Prototype Property   | Yes                      | No                    |
  | implicit return      | No                       | Yes (single expression)|
  +----------------------+--------------------------+-----------------------+

* The dynamic binding of `this`:
  - Default: In a global function, `this` refers to `window` (browser) or `global` (Node), or `undefined` in strict mode.
  - Method call: In an object method, `this` points to the object calling the method (e.g. `obj.fn()`).
  - Constructor: Inside `new Constructor()`, `this` binds to the newly created instance.

* Explicit Binding (Call, Apply, Bind):
  - call(): Invokes the function immediately, binding `this` to the first parameter, and accepts arguments individually.
    Example: `greet.call(person, "Hello", "!")`
  - apply(): Invokes the function immediately, binding `this` to the first parameter, and accepts arguments as an array.
    Example: `greet.apply(person, ["Hello", "!"])`
  - bind(): Does not invoke the function immediately. Returns a new copy of the function with the bound context and optional pre-filled arguments.
    Example: `const boundGreet = greet.bind(person, "Hello")`

* Immediately Invoked Function Expressions (IIFE):
  - Self-executing anonymous functions:
    `(function() {
       const privateVar = "scoped";
       console.log("IIFE executed");
     })();`
  - Purpose: Isolates variable scopes, preventing pollution of the global namespace (essential before ES6 modules).

4. CLOSURES & LEXICAL SCOPE
--------------------------------------------------------------------------------
* Lexical Scope:
  - Nested functions have visual access to outer scope variables based on their location in the source code.
  - Scope chain resolution is static/lexical (determined at write-time, not runtime).

* Closures:
  - Definition: The combination of a function bundled together with references to its surrounding state (the lexical environment).
  - Allows an inner function to retain access to variables of its outer function even after the outer function has finished executing.
  - How they work: The JS garbage collector does not clean up outer variables as long as there is an active reference in the closure.

* Classic Closure Loop Puzzle:
  for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);
  }
  // Output after 100ms: 3, 3, 3. (Because var is function-scoped; they all share the same bindings).
  
  Solutions:
  1. Block scope 'let' (binds unique 'i' block value for each iteration):
     for (let i = 0; i < 3; i++) {
       setTimeout(() => console.log(i), 100); // 0, 1, 2
     }
  2. IIFE (creates a private scope for each loop iteration):
     for (var i = 0; i < 3; i++) {
       (function(index) {
         setTimeout(() => console.log(index), 100); // 0, 1, 2
       })(i);
     }

* Practical Closure Use Cases:
  - Data Encapsulation (Private states/variables):
    function createCounter() {
      let count = 0; // Private variable
      return {
        increment: () => ++count,
        getCount: () => count
      };
    }
  - Memoization (Caching results of heavy computations).
  - Currying (Transforming a function of multiple arguments into sequential single-argument functions).

5. PROTOTYPES & ES6 CLASSES
--------------------------------------------------------------------------------
* Prototypal Inheritance:
  - Every object contains a private property linking to its prototype (`__proto__` or `Object.getPrototypeOf(obj)`).
  - Lookups search the object keys first. If not found, lookups climb the chain:
    `instance.__proto__` -> `Constructor.prototype` -> `Object.prototype` -> `null`.

* Proto Linkage ASCII Diagram:
  [ myDog ] ── __proto__ ──> [ Dog.prototype ] ── __proto__ ──> [ Object.prototype ] ── __proto__ ──> null
  (bark())                   (run())                             (toString())

* ES6 Classes (Syntactic Sugar for Prototypes):
  - Provides a cleaner notation. Beneath the hood, JS still sets prototype links.
  - Key components:
    - constructor(): Initializes instance properties.
    - Instance Methods: Declared without keywords, attached automatically to `Class.prototype`.
    - Static Methods: Prefixed with `static`. Bound directly to the Class constructor function, not instances.
    - Getters/Setters: Intercept property access/assignment.
    - extends & super():
      - `extends` establishes `__proto__` connection.
      - `super()` executes parent constructor, injecting parent properties and binding `this`.
      - E.g.:
        class Animal {
          constructor(name) { this.name = name; }
        }
        class Dog extends Animal {
          constructor(name, breed) {
            super(name); // Must be called before accessing 'this'
            this.breed = breed;
          }
        }

6. ASYNCHRONOUS JAVASCRIPT & THE EVENT LOOP
--------------------------------------------------------------------------------
* Event Loop Visual Model:
  +-----------------------------+
  |    JAVASCRIPT ENGINE        |
  |  +-----------------------+  |
  |  | CALL STACK (LIFO)     |  |
  |  +-----------------------+  |
  +--------------|--------------+
                 | Async Tasks (Web API)
  +--------------v--------------+
  |    WEB APIs (Browser/Node)  |  - Timers, AJAX/Fetch, Event Listeners
  +--------------|--------------+
                 | Task Ready
  +--------------v--------------+       +------------------------------+
  | MICROTASK QUEUE (High Prio) | ────> | EVENT LOOP                   |
  |  - Promise, queueMicrotask  |       | Checks Call Stack:           |
  +-----------------------------+       | If Empty -> Empties Microtask|
  +-----------------------------+       | Queue -> Runs ONE Macrotask  |
  | MACROTASK QUEUE (Low Prio)  | ────> | -> Repeats loop cycles.      |
  |  - setTimeout, I/O, event   |       +------------------------------+
  +-----------------------------+

* Execution Priority Order Example:
  console.log("1");
  setTimeout(() => console.log("2"), 0);
  Promise.resolve().then(() => console.log("3"));
  console.log("4");
  // Output order: 1 -> 4 -> 3 -> 2
  // Execution:
  // 1. Sync actions print "1" and "4" on Call Stack.
  // 2. Microtask queue contains Promise.then callback.
  // 3. Macrotask queue contains setTimeout callback.
  // 4. Stack empties -> Microtask runs ("3") -> Macrotask runs ("2").

* Promise Combinators Performance Matrix:
  +----------------------+---------------------------+--------------------------+
  | COMBINATOR           | RESOLVES WHEN             | REJECTS WHEN             |
  +----------------------+---------------------------+--------------------------+
  | Promise.all()        | ALL promises resolve      | ANY promise rejects      |
  | Promise.allSettled() | ALL settle (always resolves)| Never (returns outcomes) |
  | Promise.any()        | FIRST success resolves    | ALL promises reject      |
  | Promise.race()       | FIRST settled (resolved/rejected) | FIRST rejected   |
  +----------------------+---------------------------+--------------------------+

7. DOM MANIPULATION & EVENT FLOW
--------------------------------------------------------------------------------
* Event Propagation Phases:
  +------------------------------------------------------+
  | Window                                               |
  |   | (1. CAPTURE Phase: event travels down)       |   |
  |   v                                              ^   |
  |   [ Parent Container ]                           |   |
  |     |                                   (3. BUBBLE   |
  |     v                                    Phase:      |
  |     [ Target Element ] ────────────────── climbs up) |
  |       (2. TARGET Phase)                              |
  +------------------------------------------------------+

* Event Binding Options:
  - Bubbling (Default): `el.addEventListener('click', handler)` (Fires during bubble phase).
  - Capturing: `el.addEventListener('click', handler, true)` or `{ capture: true }`.

* Event Delegation:
  - Concept: Add a single listener to a parent container instead of separate listeners to multiple child elements.
  - Uses event bubbling to catch target element clicks.
  - Advantages: Minimizes memory usage, automatically handles dynamic elements added to the DOM later.
  - Example:
    const list = document.querySelector('#item-list');
    list.addEventListener('click', (event) => {
      // event.target is the actual clicked element
      // event.currentTarget is the listener element (#item-list)
      if (event.target.tagName === 'LI') {
        console.log("Clicked item value:", event.target.textContent);
      }
    });

* Event Controls:
  - preventDefault(): Blocks the browser's default behavior for the event (e.g. form submission page reloading, anchor tag navigating).
  - stopPropagation(): Prevents the event from traveling further up or down the propagation path.

8. ESSENTIAL ARRAY & OBJECT METHODS
--------------------------------------------------------------------------------
* Pure vs. Impure Array Methods:
  - Pure (Returns a new array, does not mutate original):
    `map()`, `filter()`, `slice()`, `concat()`, Spread operator `[...arr]`.
  - Impure (Mutates the original array directly):
    `push()`, `pop()`, `shift()`, `unshift()`, `splice()`, `sort()`, `reverse()`.

* Reduce Accumulator States:
  - Syntax: `arr.reduce((accumulator, currentValue, index, array) => { ... }, initialValue)`
  - Crucial rule: Always specify the `initialValue` to prevent syntax bugs on empty arrays or incorrect type assumptions (if omitted, first element is used as initial value).
  - Example: Counting word frequencies:
    const words = ['apple', 'banana', 'apple'];
    const count = words.reduce((acc, word) => {
      acc[word] = (acc[word] || 0) + 1;
      return acc;
    }, {}); // {} is initialValue

* Object Cloning:
  - Shallow Copy (clones base properties; nested object references are shared):
    - `const copy = { ...original };`
    - `const copy = Object.assign({}, original);`
  - Deep Copy (creates entirely independent objects recursively):
    - Modern native API: `const copy = structuredClone(original);` (Highly recommended, handles cyclic refs).
    - Legacy fallback: `const copy = JSON.parse(JSON.stringify(original));` (Loses functions, Date objects, undefined, RegExp, Map/Set).

9. MODERN ES6+ FEATURES
--------------------------------------------------------------------------------
* Destructuring:
  - Extract properties from objects/arrays into clean variables.
  - Fallbacks & Aliases:
    const user = { username: "sahil", details: { age: 24 } };
    const { username: displayName, details: { age }, role = "user" } = user;
    // displayName = "sahil", age = 24, role = "user" (default fallback)

* Spread (`...`) vs. Rest (`...`) Operators:
  - Spread: Expands/unpacks iterables or objects.
    - Array unpacking: `const newArr = [...arr1, ...arr2]`
    - Object cloning/merge: `const merged = { ...obj1, ...obj2 }`
  - Rest: Gathers multiple values into a single array structure.
    - Function signatures: `const sum = (...args) => args.reduce((a, b) => a + b)`
    - Array splitting: `const [first, ...rest] = [10, 20, 30]`

* Optional Chaining (`?.`):
  - Safely navigates nested paths. Stops execution and returns `undefined` if reference is nullish (`null` or `undefined`).
  - Short-circuits instantly. E.g.: `const avatar = user?.profile?.avatar;`

* Nullish Coalescing (`??`) vs. Logical OR (`||`):
  - `??` evaluates right-side expression only if left-side is `null` or `undefined`.
  - `||` evaluates right-side if left-side is any Falsy value (`0`, `""`, `false`, `NaN`, `null`, `undefined`).
  - Comparative Example:
    const speed = 0;
    const finalSpeedOR = speed || 10;   // 10 (because 0 is falsy)
    const finalSpeedNC = speed ?? 10;   // 0  (because 0 is NOT nullish)

10. LOOP TYPES & ITERATION
--------------------------------------------------------------------------------
* Loops Comparison Matrix:
  +------------+-------------------------+----------------------+--------------------+
  | LOOP TYPE  | TARGET                  | ACCESS TO            | BREAK/CONTINUE     |
  +------------+-------------------------+----------------------+--------------------+
  | for        | Standard Counters       | Index                | Yes                |
  | while      | Dynamic Conditions      | Loop state           | Yes                |
  | do...while | Runs at least once      | Loop state           | Yes                |
  | for...in   | Enumerable Object Keys  | Keys (Strings)       | Yes                |
  | for...of   | Iterable values         | Values               | Yes                |
  | forEach()  | Array Elements          | (value, index, arr)  | No                 |
  +------------+-------------------------+----------------------+--------------------+

* Loops Mechanics & Performance Notes:
  - for...in: Iterates over keys, including inherited enumerable prototype keys.
    Always guard with `hasOwnProperty()` to avoid prototype key bleed:
    if (obj.hasOwnProperty(key)) { ... }
  - for...of: Uses ES6 iterators (object must implement `[Symbol.iterator]`).
  - forEach():
    - Iterates array items.
    - You cannot use `break`, `continue`, or `return` to halt execution.
    - If early exit is needed, use `for...of` or standard `for`, or use array search methods like `some()`, `every()`, `find()`.
